# Changelog

All notable changes to CreatorCanvas are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [0.3.0] - 2026-11-26

Feature and usability release: command palette, three built-in resource packs
with a searchable browser, four new sample projects, a guided first run
(belcome dialog, quick tour, "First steps" panel, live hints) and the first
memory guards (undo budget, adaptive render cache).

### Added

- **Pack items can declare their blend mode** — `pack.json` now accepts
  `items[].blend` (e.g. `"screen"`), so a pack can ask for a specific
  compositing mode without touching code. The 16 overlays declare `screen`;
  `MainWindow::applyPackItem` reads it via
  `PackStore::itemForResource()` instead of sniffing the file path. Covered by
  `test_pack_blend`.

- **Search in the pack browser** — with 71 resources a search field was due;
  it filters by the translated label or the manifest key and composes with the
  category filter. Covered by `test_pack_browser_search`.

- **Memory budget for the undo history** — the stack was limited only by
  step count (100), and each bulky step (pixel selections, masks, image
  resize) keeps a full bitmap, so a 4000×3000 document could retain ~4.8 GB
  before the count limit was reached. `Command` now exposes
  `estimatedBytes()`, the stack enforces `byteBudget` (default **512 MB**,
  configurable in Settings: *Memory budget for history*) and always keeps at
  least one step; `MainWindow` supplies an asset-footprint probe so bitmaps
  living in the `AssetStore` are counted too. Covered by
  `test_history_budget`.
- **Adaptive render-cache budget** — `CanvasRenderer` reads the machine's
  total memory (`/proc/meminfo`) and scales the per-layer cache and the
  composite budget (96/48 MB on 4 GB machines, 192/96 on 8 GB, 256/96 on
  16 GB+) instead of always reserving 256 + 96 MB.
- **Export dialogs remember the last folder** (`general/lastExportDir`),
  falling back to the project folder and then home — no more hunting for the
  destination on every export.

- **Two more resource packs**: `texturas` (32 textures — papers, cracked
  wall, carpet, plastics, topographic and abstract backgrounds, scratches,
  torn papers; JPEG progressive q80 at 1280 px) and `sobreposicoes`
  (16 alpha overlays — six dust/noise and ten grunge; greyscale+alpha PNG at
  900–1100 px, ~44% smaller than RGBA without visible loss). The pack browser
  now builds its category filter from the manifests, so new packs/categories
  need no code change, overlay thumbnails are composited over mid-grey so the
  pattern is visible, and applying an overlay to an open document adds it as a
  covering layer with **Screen** blending. `test_pack_store` covers all 71
  items, every translated label and the filters.

- **Four sample projects built on the Starter Pack** (`exemplos_projetos/09`–`12`,
  generated by `tools/generate_pack_samples.cpp`): a 1280×720 thumbnail on the
  blue-dots background, a 1920×1080 YouTube end screen, a 1080×1350 textured
  Instagram post and a 1500×500 ember banner — all with editable placeholder
  text. They appear as new cards in the start screen's *Practice Scenarios*
  section (titles/descriptions translated in en/pt-BR/sv) and are covered by
  `test_sample_projects`, which loads all twelve samples and checks layers and
  embedded thumbnails.

- **Resource packs** (`resources/packs/`, `services/packstore.{h,cpp}`,
  `ui/packbrowser.{h,cpp}`) — the built-in **Starter Pack** ships 23 curated
  assets from the user's own editing pack and is browsable from the start
  screen, `Layer ▸ Backgrounds & textures...` (`Ctrl+B`) and the command
  palette: 6 thumbnail backgrounds, 12 textures and 3 ready-made YouTube end
  screens. Choosing an item with no document open creates the document at the
  image's exact size (it becomes the canvas); with a document open it is added
  as a fitted layer. The pack is embedded through `resources/packs.qrc`
  (`:/packs`), described by `pack.json` and documented in
  `resources/packs/README.md` (2.9 MB total, JPEG progressive / PNG, no source
  metadata).

- **First-run welcome dialog** (`ui/welcomedialog.{h,cpp}`) — language
  picker plus what the app is for; appears once in the normal startup path
  (never in `--smoke-test`/`--ui-snapshot`), the choice is persisted in
  `general/welcomeShown`.
- **Quick tour** (`ui/onboardingtour.{h,cpp}`) — a four-step guided tour with
  a popup anchored to the tool bar, tool options, layers panel and export
  button. Runs once automatically after the first document settles; can be
  replayed any time from **Help ▸ Quick tour** (which re-arms the flag).
- **"First steps" panel** (`ui/onboardingpanel.{h,cpp}`) — a dock with four
  goals that tick themselves off as the user works (create/open a document,
  add an image or text layer, select and arrange layers, export). It hides
  itself once everything is done, and only shows in the editor.
- **Two more status-bar hints** — pressing Delete with nothing selected now
  explains how to select a layer instead of doing nothing, and selecting a
  text layer mentions that double-click edits the text.

- **Live help for beginners:**
  - a **status-bar hint** per tool (what it does + the modifier keys, e.g.
    "Brush - drag to paint. [ and ] change the brush size");
  - a **centred hint on the empty canvas** ("The canvas is empty — drag an
    image here · press T for text · Ctrl+K finds any command") that disappears
    as soon as the document has layers;
  - a **dismissible tips bar** above the editor on first run ("New to
    CreatorCanvas? Press Ctrl+K…"), dismissed once and never shown again
    (`general/hintsBarDismissed`);
  - two direct links in the start screen's empty state (**See all keyboard
    shortcuts**, **Open an example project**).
- **`Layer ▸ Save Layer as PNG...`** (`Ctrl+Alt+E`) — the per-layer quick
  export that only existed in the layers-panel context menu is now a first-class
  command (searchable, shortcut-configurable).

- **Command palette** (`Ctrl+K`, `Help ▸ Command Palette…`) — incremental search over every
  registered action (menus, tools, shapes, filters, adjustments) with substring
  and subsequence matching, keyboard navigation and `Enter` to run. New
  `CommandPalette` (`src/ui/commandpalette.{h,cpp}`) plus
  `ActionManager::allActions()` / `actionId()`.
- **Every action is now registered** in the shortcut registry — the 8 extra
  shapes, 11 artistic filters, `Select ▸ Modify`, safe zones, layer comps, web
  slices, advanced mode and sample projects were previously absent, so they
  could not be searched, listed or given a shortcut.
- **File ▸ Save PNG Copy…** (`Ctrl+Shift+E`) — one-step PNG export of the whole
  document (single file dialog, fixed quality, status-bar confirmation),
  mirroring the existing per-layer quick export.
- **Advanced mode is now a Settings checkbox** (`Settings ▸ Advanced mode`),
  applying immediately, so the simple/advanced switch is discoverable instead
  of living only in the Window menu.
- New regression suite `test_command_palette` (registry coverage, filtering,
  execution and translation).

### Changed

- **Icons are memoized** — `ThemeIcons` renders each vector icon once into a
  keyed cache instead of re-rendering 3 pixmaps through `QPainter` on every
  call (the layers panel alone re-requested them per row on every refresh).
  Icons now render at 16/32 px, the only sizes the UI asks for.
- **Export confirmations moved to the status bar** (full export, quick exports)
  instead of modal popups; only failures still raise a dialog.
- **Packaging** — the AppImage/DEB scripts hard-link the three identical
  `libonnxruntime` copies (−31 MB of staging) and strip the installed
  binaries; the stale renderer-cache comment in `IRenderer.h` now matches
  `CanvasRenderer.cpp`.

### Fixed

- **Image ▸ Image Size…** resamples image assets and alpha/vector masks with
  Nearest Neighbor, Bilinear or Bicubic. Selections (active, previous and
  saved), guides, slices and nested/shared assets are transformed coherently;
  undo/redo uses snapshots and never resamples cumulatively.
- **Select ▸ Transform Selection…** moves, scales or rotates only the selection
  outline with a preview, explicit Document/Layer space and undo.
- **Smart Filters**: Blur, Motion Blur, Noise, Twirl, Pinch and Ripple now open
  a parameter dialog and create editable, linked `AdjustmentLayer`s by default.
  A destructive option remains available and respects the active selection.
  Adjustment type/parameters and both linked IDs persist in `.creatorcanvas`.
- **Draggable guides** can be pulled from the horizontal/vertical rulers.
- **Batch** now uses the robust image importer (including PSD composites) and
  supports PDF/SVG output in addition to PNG/JPEG/WebP.
- New regression suites: `test_batch`, `test_selection_transform`,
  `test_image_size`, and `test_smart_filters`.

### Fixed

- **Closing a modified document in any automated mode hung the process** —
  `confirmDiscardUnsavedChanges()` opened the modal "save / discard / cancel"
  box even when `suppressStartupInteractions` was set, which exists precisely
  to keep `--smoke-test`, `--ui-snapshot` and the test suites modal-free (the
  constructor comment already promised it). Now it returns immediately, and
  `packOverlayAppliesOnceWithScreenBlend` covers the whole
  browser → import → blend path that exposed it.

- **`Ctrl+B` was bound to two commands** (`View ▸ Tools bar` and the new
  `Layer ▸ Backgrounds & textures…`), so an ambiguous shortcut fired both.
  The pack browser moves to **`Ctrl+Shift+B`**, and `test_shortcuts` now fails
  if any two registered actions ever share a default shortcut again.
- **Applying an overlay could hit the wrong layer** — `applyPackItem`
  adjusted whatever layer was selected instead of the one it had just
  imported, silently rescaling the user's layer. It now tracks the layer the
  importer created (top of the root group before/after), selects it, and only
  then applies the Screen-blend cover transform.

- **Applying a pack item created TWO layers** — `PackBrowser` listened to both
  `itemActivated` and `itemDoubleClicked`, and a double click emits both, so
  the item was imported twice. Only `itemActivated` is connected now (it
  already covers double click and Enter), plus an `m_activated` guard that is
  reset in `showEvent`. Covered by `test_pack_browser_activation`.

- **"First steps" panel was a dead end and barely appeared** — it had no way to
  dismiss it (closing the dock did not persist, and it came back on the next
  document/selection change), its dock title was empty, and
  `enterEditor()` refreshed it *before* switching to the canvas, so on first
  entry it never showed at all. Now the panel has a **Skip for now** button,
  dismissal is persisted (`general/onboardingDismissed`) for both the button
  and the dock's close corner, the title is translated, `enterEditor()`
  switches the stack first, and `showEvent()` re-evaluates the panel (the
  `--ui-snapshot` path shows it only reached the editor before the window was
  shown). Covered by `onboardingPanelDismissPersists` and
  `test_onboarding_dismiss`.

- **Autosave no longer fires under a modal dialog** — besides the existing
  "mouse button held" deferral, an open modal (export, adjustments, AI) also
  postpones the save by 3s, so a routine save never freezes the UI behind a
  dialog or captures a transient state.

- **Handles and scale/rotate gestures now use the full layer-to-document
  transform**, including all parent groups. Previously a layer inside a moved
  or rotated group could render in one place while its handles appeared
  elsewhere; scaling now preserves the opposite anchor in that same space.
  Regressions cover parent rotation and fixed-point preservation.
- **Group pivot is preserved when children move** — `Document::setLayerTransform`
  now compensates the group's `contentBounds` center delta by its linear
  transform, so moving a child no longer cancels the movement through a changing
  group matrix. Handle/hit-test composition now follows the renderer's
  layer × parent order, including rubber-band hit-testing.
- **Selection spaces survive the full workflow** — save/load/reselect/invert,
  undo/redo, Paste Into, asynchronous filters and raster tools preserve the
  explicit space and compose transforms in renderer order.
- **Snap respects groups** — moving/target rectangles include all ancestor
  transforms, the moving subtree is excluded from its own snap targets, and the
  snap delta is converted back to the parent's coordinate space.
- **Clipboard includes linked adjustments automatically**, including nested
  groups, with reciprocal ID remapping and no duplicates.
- **Responsive docks** register Navigator/Swatches after their creation and
  correctly restore their visibility after compact layout cycles.
- **Adjustment links persist**: `sourceLayerId` and `adjustmentLayerId` are
  serialized so Smart Filters remain linked after reopening a project.
- Batch and Workspace Layout dialogs now use the translation catalogs; the GPU
  option is explicitly disabled until a real GPU backend exists.
- **Image Size dialog labels are translated** in en/pt-BR/sv (`common.imageSize.*`
  keys added; previously raw keys like `common.imageSize.width` were shown).
- **Refine Edge is responsive again**: slider changes are debounced (80 ms) and
  the live preview refines a downscaled mask (max 320 px, radii scaled
  accordingly); the accepted result still refines the full-resolution mask.
  Buttons are translated instead of hardcoded Portuguese.

## [0.3.0] - 2026-11-24

Feature and stabilization release: multi-layer clipboard, persistent
selection/canvas operations, hybrid export, new panels, and a systematic
correctness pass over grouping, rendering caches and user workflows.

### Added

- **Clipboard** (`Edit ▸ Copy/Cut/Paste`, Ctrl+C/X/V, plus `Paste Into Selection`,
  Ctrl+Shift+V) — copies the selected layer(s) to an internal clipboard (keeps
  type and styles) and to the system clipboard as a rendered image, so pasting
  works across applications too. Paste inserts as a new layer on top; paste-into
  applies the active selection as an alpha mask. All undoable.
- **Selection channels** — `Select ▸ Save Selection…` stores the active pixel
  selection under a name with explicit Document/Layer space,
  `Select ▸ Load Selection` lists and
  restores them, and `Select ▸ Reselect` (Ctrl+Shift+D) restores the previous
  selection. All selection changes remain single undo steps.
- **Edit ▸ Fill / Stroke / Clear** — paint the foreground colour inside the
  active selection, stroke its outline (adjustable width), or delete its pixels,
  all constrained to the selection mask and committed as one undo step.
- **Layer ▸ Duplicate Layer**, **Merge Down** and **Rasterize Layer** menu
  actions (previously only in context menus): duplicate deep-copies the selected
  layer via `DuplicateLayerCommand`, merge-down reuses `LayerOperations::mergeSelected`
  with a single id, and rasterize renders text/shape/vector/fill/adjustment
  layers into an image layer via `ReplaceLayersWithRasterCommand`.
- **Image ▸ Canvas Size…** (width/height + 3×3 anchor) and
  **Image ▸ Rotate Canvas** (90° CW/CCW, 180°) — new `Document::setCanvasSize()`
  / `Document::rotateCanvas()` with the `canvasSizeChanged` signal and the
  undoable `ResizeCanvasCommand` / `RotateCanvasCommand`. Canvas rotation only
  transforms root-level layers (group transforms cascade to children, avoiding
  double rotation).
- **Tests**: `test_saved_selections` (previous-selection tracking, reselect
  through the history stack, saved-selection CRUD) and `test_canvas_ops`
  (canvas resize with anchor offset, 90°/180° rotation math, undo/redo of both
  commands, group double-rotation guard), plus merge-down and single-layer
  rasterize cases in `test_layer_operations`.
- **Saved selections persist** in `.creatorcanvas` projects (optional
  `savedSelections` key + `selections/<id>.png` ZIP entries; old readers ignore
  them, invalid entries are skipped on load). Same round-trip test coverage.
- **Filter gallery**: `Filter ▸ Blur` (Gaussian, Motion with angle/length),
  `Filter ▸ Noise` (Add Noise, 0–100%, mono option), `Filter ▸ Distort`
  (Twirl/Pinch/Ripple, inverse-mapped warps) — new `ImageProcessing` functions
  with deterministic tests; applied to the active image layer respecting
  locks and the active selection, committed as one undo step.
- **Export PDF and SVG** — `exportDocumentToPdf()` (QPdfWriter through the
  vector-capable software path) and `exportDocumentToSvg()` (shapes/vector/text as real SVG
  elements via QXmlStreamWriter; images and complex shapes embedded as PNG;
  gradients, blend modes, opacity and transforms mapped). Both added to the
  export dialog format combo (layer-only scope disabled for them).
- **PSD import (minimal, safe)** — `decodePsdComposite()` reads the flattened
  8/16-bit grayscale/RGB composite, raw or PackBits RLE, with strict
  bounds-checked parsing and pixel caps; re-encoded to PNG for the AssetStore.
  PSB/CMYK/layers are rejected with a clear error.
- **Rulers and guides** — `View ▸ Show Rulers` (overlay rulers with 10/100 px
  ticks), `View ▸ Guides` (show/new/clear; guides are document data, serialized
  in the project and drawn as cyan dashed overlay lines).
- **Info in the status bar** — cursor position now also shows the hex color and
  alpha of the pixel under the cursor on the active image layer.
- **Navigator and Swatches panels** — new docks (`Window ▸ Navigator /
  Swatches`): Navigator shows a live thumbnail with the viewport rectangle and
  click/drag-to-pan; Swatches is a persisted color palette (click to set the
  paint color, "+" adds the current color, right-click removes).
- **Refactor**: selection/clipboard/filter-apply methods moved from
  `mainwindow.cpp` to `ui/mainwindow_selection.cpp` (pure code move, no behavior
  change) — first incremental step of the documented MainWindow split.

### Fixed

- **Slow canvas after applying a linked adjustment** — image layers with an
  `adjustmentLayerId` are excluded from the layer pixmap cache, so the
  adjustment was re-applied per pixel on EVERY repaint. The adjusted result is
  now cached on the layer itself (`adjustedRenderCache`), keyed by the input
  bitmap cacheKey plus a hash of the adjustment state (kind/opacity/parameters),
  so it only recomputes when something actually changed. Benchmark on a
  2000×1500 layer with Vignette: first render 1054 ms → subsequent repaints
  4.5 ms (~235×). Covered by `linkedAdjustmentRendersAndInvalidatesOnParamChange`
  in `test_renderer` (cache hit is stable, param change invalidates correctly).
- **Adjustments dialog preview** is now debounced (60 ms) while dragging
  sliders, instead of re-running the per-pixel preview + histogram on every
  step; the applied result is unaffected (`accept()` recollects parameters).
- **Linked adjustment layers were applied twice** (once at the image level in
  `drawLayer`, again at the tree level in `composeLayers`, because any visible
  adjustment layer forced the compositing path) — the bench showed gray 100 +
  brightness 50 rendering as 255 instead of 228. Now linked adjustments
  (`sourceLayerId` set) are skipped in the compositing path and no longer force
  it (`subtreeNeedsCompositing`), so they apply exactly once.
- **Frozen UI while dragging layers with adjustments in the stack** — the
  compositing path re-ran every adjustment per pixel over the full canvas on
  every interactive frame (revision changes per frame, so the composite cache
  never hit). Linked adjustments now take the fast path entirely, and the
  compositing path renders interactive frames into a downscaled buffer
  (≤1200 px, not cached). Benchmark on 1280×825 with 2 images + 2 linked
  vignette adjustments: drag frame 125–166 ms → **7.95 ms**, idle repaint
  0.9 ms.
- **Linked adjustment layers now affect only their image** — previously a
  linked adjustment was also applied to the whole accumulated stack in
  `composeLayers` (so every image below changed too). Tree-level application
  now skips linked adjustments, and hiding the adjustment layer removes its
  effect (visibility is part of the adjustment cache key). Regression tests:
  `linkedAdjustmentAffectsOnlyItsImage`, `unlinkedAdjustmentAffectsAllBelow`.

### Fixed

- **Grouping moved the content to the top-left corner** — a new group was
  created with `transform.position = (0,0)`, and the group matrix
  `T(pos)·T(-contentCenter)` shifted everything by `-center`. Fixed by keeping
  the invariant "group matrix = identity" (`position = content center in parent
  space`): `GroupLayersCommand` recenters the new group,
  `ReorderLayerCommand` converts the moved layer into the group's local space
  (`G⁻¹·M`) and keeps the target group's matrix unchanged when its bounds grow,
  and `UngroupLayersCommand` bakes the group matrix into the children
  (`G·M`) so moving a group then ungrouping preserves positions. Render-verified
  (`groupKeepsVisualPosition`, `reorderIntoGroupKeepsPositions`,
  `ungroupAfterMovingGroupKeepsPositions` in `test_layer_operations`).
- **Legacy projects with misplaced groups are migrated on load** — projects
  saved before the group fix stored groups with `position=(0,0)` (which made
  the group matrix shift content to the top-left corner). The project reader
  now detects exactly that signature (default rotation/scale/shear and
  `position==(0,0)`) and recenters the group, so old `.creatorcanvas` files —
  including autosave recovery files — open with content in place. Test:
  `legacyProjectGroupIsMigratedOnLoad`. The history-less `groupSelected`
  fallback also recenters the new group now.
- **Selection/project coherence** — active and saved selections now carry an
  explicit Document/Layer space; Canvas Size/Rotate transforms masks, guides and
  web slices with full undo/redo. Invalid document-space state is rejected
  before saving, while legacy projects remain readable.
- **Nested group transforms** — root↔group, group↔group and multi-parent
  grouping preserve complete affine matrices, including flip and shear, with
  invalid/cyclic reorders rejected before mutation.
- **Renderer cache correctness** — cached blits reapply blend modes, composite
  byte accounting/eviction is bounded, and outline/drop-shadow use masked pixels
  with source-aware cache keys. `renderSiblingLayers` uses the correct clipping
  base, and one document fingerprint is computed per render call.
- **Clipboard hardening** — multi-layer and cross-document asset remapping,
  correct adjustment/text-path links, no accidental masking on empty paste, and
  stale internal snapshots never override newer external clipboard content.
- **Export fixes** — SVG no longer applies transforms twice, scale reaches the
  backend, PDF uses the vector-capable software path, and PSD 16-bit PackBits is
  decoded correctly. Export controls now match actual format behavior.
- **Filter/UI fixes** — cancellation is consistent, mono Noise is available,
  selection size mismatches no longer apply a filter globally, and heavy filters
  run asynchronously with stale-result protection.
- **Navigator/Swatches/docks** — initial thumbnail construction, colour
  synchronization, responsive visibility, translated titles and safe teardown.

## [0.2.2] - 2026-11-20

Stabilization release: reliable image adjustments and canvas zoom, resilient
ONNX Runtime packaging, MiniPaint integration fixes, and cross-platform CI
hardening.

### Added

- **MiniPaint integration (`Image ▸ Edit in MiniPaint`)** — the Paint-like
  editor module is vendored under `3rdparty/minipaint`, built in-tree and
  shipped beside `CreatorCanvas` (DEB, AppImage and the Windows portable ZIP
  now all include it, with its SFML 3 runtime). The bridge is non-blocking
  (the interface stays responsive while the editor is open) and logs the
  phase timings.
- **Export dialog** rework — one row of platform preset chips replaces the
  duplicated dropdown, transparency toggle preserved across format changes,
  live checkerboard preview, translated dimension/size labels.
- **Export transparency** (`transparentBackground`) honoured by
  `exportDocumentToImage()` / `exportLayerToImage()`; JPEG stays opaque.
- **ICC preservation and export tagging** — PNG/JPEG/WebP imports preserve
  their original profile through the native project and back into exported
  documents, layers and web slices. System-profile fallback supports common
  ICC/ICM names; tagging is atomic, strict on malformed payloads and a
  graceful no-op when no profile is available. Imports into an existing
  document convert supported RGB profiles to its working space with
  `QColorSpace` and losslessly re-encode the converted asset.
- **Tests**: MiniPaint launch contract (`test_minipaint_bridge`), export
  transparency behaviour (`test_export_dialog`), the MiniPaint module's
  own smoke/regression suite (`minipaint_smoke`, skips without a display),
  the widget-free viewport (`test_canvas_transform`) and ICC round trips
  (`test_icc`).
- **Photoshop-style flyout tool slots** — 9 consolidated slots in the toolbar.
- Pixel grid at ultra-high zoom; auto-save deferred while the mouse is busy.

### Changed

- **MiniPaint drawing performance** — incremental compositing during strokes
  (~210× cheaper per pointer event at 1920×1080, two layers) and redraw only
  when something changes instead of a constant 60 fps UI loop.
- AppStream metadata validates (`<p>`-wrapped release descriptions) and is
  installed under its component ID; the AppImage version is read from
  `project()` instead of `cmake_minimum_required`.
- `LayerOperations` moved from `core/operations` to `services`.
- `CanvasView`'s zoom/pan/fit block extracted into the widget-free
  `CanvasTransform` unit (`src/ui/canvastransform.{h,cpp}`), covered by
  `test_canvas_transform`.
- **Healing/Retouch performance** — one stable snapshot/detach per stroke,
  in-place premultiplied processing and patch-only preview restoration
  replace full-layer copies on every pointer event. Tests prove output
  remains pixel-identical for all six retouch modes and healing.
- **Multi-stop and conical gradients** are now available in the normal
  shape inspector, not only in advanced mode.

### Fixed

- Export estimated size and dimension labels were hardcoded English and now
  use the translation catalogs.
- `MiniPaintBridge` no longer freezes the application or spins a wait cursor
  while the external editor is open, and refuses to start a second session.
- Duplicated scale entries accumulating in the export dialog's scale combo.
- MacOS-safe handling of a disabled transparency toggle (state preserved
  across JPEG round-trips).
- Marquee selection on rotated/sheared image layers now follows the actual
  document-space shape instead of collapsing to an axis-aligned bbox.
- Layer Comp undo restores properties through `Document` setters and emits
  the required change notifications instead of assigning fields silently.

## [0.2.1] - 2026-11-04

M21–M23 feature work and hardening: clipping masks (also inside groups),
perspective mockups with a free-form mode, pen (Bézier) tool,
marquee/gradient/retouch/healing tools, batch processing, workspace layouts,
customizable shortcuts, scanline flood fill and magic wand, and DEB/NSIS
packaging fixes.

## [0.2.0] - 2026-09-08

Phase 2 release: AI background removal, raster tools (Crop, Scissors, Wand,
Clone Stamp), Paint & Flood Fill brushes, text gradients, 3D tilt
perspective, and color adjustments.

## [0.1.0] - 2026-08-26

Initial release: layers, image import, text, shapes, presets, undo/redo,
export.
